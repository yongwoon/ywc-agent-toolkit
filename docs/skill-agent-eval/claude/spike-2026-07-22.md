# Phase 0 Adapter Spike — Claude Code 격리 실행 가능성

> Spec: `docs/ywc-plans/claude-skill-eval-runner.md` (AC1)
> Date: 2026-07-22 · CLI: `claude` 2.1.217 (native, darwin-arm64)
> Total spend: **$0.5409** (3 dispatch 중 2건은 $0 로 단락)

## 판정: `best-effort, credential-gated`

격리 수단은 **존재한다** — `CLAUDE_CONFIG_DIR` 이 user-level 설정 루트를 재배치한다. 그러나 **인증이 같은 루트에 있어 함께 잘려나간다.** 따라서 등급은 `unavailable`(수단 없음)도 `isolated`(끝까지 입증)도 아니다.

Codex spec Iteration 2 가 예측한 credential-provider 문제가 Claude Code 쪽에서도 그대로 재현되었다. 남은 것은 **자격증명 핸드오프 선택**이며, 그것이 정해지면 등급은 `isolated` 로 올라갈 수 있다.

## 방법

주관적 판정을 없애기 위해 **sentinel skill** 을 썼다. `/tmp/ywc-spike/ws/.claude/skills/ywc-spike-sentinel/SKILL.md` 는 호출되면 `SENTINEL_OK_7Q4X` 만 출력한다. "발동했는가" 는 문자열 포함 여부로 결정되며 해석의 여지가 없다.

## 6개 미확인 항목의 결과

### 1. `CLAUDE_CONFIG_DIR` — **VERIFIED (존재하며 재배치함)**

`claude doctor` 를 환경변수 유무로 두 번 실행해 비교했다. API 호출 없음.

| 항목 | 기본 | `CLAUDE_CONFIG_DIR=/tmp/ywc-spike/home` |
|---|---|---|
| Config install method | `native` | **`not set`** |
| Last update attempt | `success → 2.1.217` | **`none recorded`** |
| Remote Control | 정상 | **`Not signed in to claude.ai`** |

실행 후 임시 디렉터리에 `.claude.json` 과 `backups/` 가 **생성되었다** — 변수가 읽기·쓰기 양쪽에서 존중된다.

### 2. "선택한 skill 하나만 로드" — **PARTIALLY VERIFIED**

- **프로젝트 로컬 `.claude/skills/` 는 로드된다** (Test A 에서 sentinel 발동 확인).
- 임시 `CLAUDE_CONFIG_DIR` 은 user-level 루트를 갈아치우므로 원리상 243개 설치본이 빠진다.
- **다만 끝까지 입증하지 못했다** — Test B 가 skill 해석 단계에 도달하기 전에 인증에서 실패했다.
- `--plugin-dir` / `--settings` 는 help 문언상 **추가(additive)** 이며, 이번에 필요하지 않아 검증하지 않았다.

### 3. `--disable-slash-commands` 범위 — **VERIFIED**

프로젝트 로컬 skill 까지 **끈다**. `claude -p "/ywc-spike-sentinel" --disable-slash-commands` → `Unknown command: /ywc-spike-sentinel`, exit 0, **cost $0**(모델 호출 없이 단락).

→ Phase 4 ablation 의 **without-arm 으로 유효**하다. 단 slash 호출은 $0 로 끝나므로, 실제 ablation 은 자연어 프롬프트로 수행해야 with/without 이 대칭이 된다.

### 4. `-p` 모드 발동 — **VERIFIED (slash), UNVERIFIED (auto-activation)**

`claude -p "/ywc-spike-sentinel" --output-format json` → `result` 가 정확히 `SENTINEL_OK_7Q4X`, `is_error: false`, `num_turns: 1`.

description 기반 **자동 활성화는 검증하지 않았다** (추가 dispatch 비용을 아끼기 위해 보류).

### 5. 인증 — **VERIFIED (부정적)**

임시 config dir 에서: `result` = **`Not logged in · Please run /login`**, `is_error: true`, exit 1, cost $0.

자격증명 소재 조사:
- 실 설정 파일은 `~/.claude.json` (198,549 bytes, 최상위 키 85개, `oauthAccount` 포함). `~/.claude/.claude.json` 은 **없다**.
- 임시 config dir 이 만든 `.claude.json` 은 503 bytes / 9키 / 인증 키 없음.
- macOS Keychain 은 service `"Claude Code"` 로 조회되지 않았다.

**`ANTHROPIC_API_KEY` 경로는 검증 불가** — 이 환경에 변수가 설정되어 있지 않다. `claude setup-token`(장기 토큰) 도 미검증.

> **수행하지 않은 검증과 그 이유**: `~/.claude.json` 을 임시 config dir 로 복사하면 격리와 인증을 동시에 얻을 수 있는지 확인할 수 있었으나, **OAuth 토큰을 공용 `/tmp` 에 복사하는 것은 실질적 보안 위험**이므로 사용자 승인 없이 수행하지 않았다.

### 6. `--output-format json` 활성화 신호 — **VERIFIED (부정적)**

페이로드 최상위 키 전량:

```
type, subtype, is_error, api_error_status, duration_ms, duration_api_ms,
ttft_ms, ttft_stream_ms, time_to_request_ms, num_turns, result, stop_reason,
session_id, total_cost_usd, usage, modelUsage, permission_denials,
terminal_reason, fast_mode_state, uuid
```

**어떤 skill 이 활성화되었는지를 나타내는 필드가 없다.** `permission_denials: []`, `stop_reason: end_turn`, `subtype: success` 모두 활성화와 무관하다.

→ spec 의 `activation_observability: unavailable` 경로가 실제로 발동한다. 판정은 **outcome(산출물) 단독**으로 해야 하며, 이는 Codex spec Iteration 1 AC12 를 그대로 계승한다.

### 7. (추가 발견) `--bare` 모드 — 격리와 구독은 배타적일 수 있다

리포트 초안 이후 `claude --help` 를 다시 읽다가 찾았다. **`--bare` 는 사실상 이 프로젝트가 원하던 격리 모드다.**

> Minimal mode: skip hooks, LSP, plugin sync, attribution, auto-memory, background prefetches, keychain reads, and CLAUDE.md auto-discovery. Sets `CLAUDE_CODE_SIMPLE=1`. **Anthropic auth is strictly `ANTHROPIC_API_KEY` or `apiKeyHelper` via `--settings` (OAuth and keychain are never read).** 3P providers (Bedrock/Vertex/Foundry) use their own credentials. **Skills still resolve via `/skill-name`.** Explicitly provide context via: `--system-prompt[-file]`, `--append-system-prompt[-file]`, `--add-dir` (CLAUDE.md dirs), `--mcp-config`, `--settings`, `--agents`, `--plugin-dir`.

의미가 두 갈래다.

**좋은 쪽** — plugin sync·auto-memory·CLAUDE.md 자동 탐색을 끄면서 **skill 은 `/name` 으로 계속 해석된다.** `CLAUDE_CONFIG_DIR` 보다 목적에 더 정확히 맞는 도구일 수 있다.

**나쁜 쪽** — **OAuth 와 keychain 을 절대 읽지 않는다.** 즉 `--bare` 를 쓰는 순간 구독 인증이 원천 차단되고 `ANTHROPIC_API_KEY` 또는 `apiKeyHelper` 만 남는다.

현재 계정은 `authMethod: "claude.ai"`, `apiProvider: "firstParty"`, `subscriptionType: "max"` 다(`claude auth status`, 읽기 전용 확인). Test A 가 쓴 $0.5409 는 **이미 이 구독으로 결제된 것**이다 — 즉 비격리 실행에는 API key 가 필요 없다.

따라서 **격리와 구독이 상충한다**는 것이 이번 spike 의 가장 중요한 제약이다. 초안에 없던 축이며, 자격증명 결정을 단순한 "어느 핸드오프를 고를까" 가 아니라 **"격리를 살릴 것인가 구독을 살릴 것인가"** 로 바꾼다.

미검증으로 남은 탈출구는 `claude setup-token` 이다. *"Set up a long-lived authentication token (**requires Claude subscription**)"* 라는 설명 자체가 구독 기반 헤드리스 인증을 위한 경로임을 가리킨다. 그것이 발급하는 토큰이 임시 config dir 또는 `--bare` 에서 통한다면 구독으로도 격리가 성립한다. **실행하지 않았다** — `--help` 에 옵션이 없어 대화형 플로우로 보이고, 실행 시 실제 자격증명이 발급되므로 사용자 승인 없이 수행할 사안이 아니다.

## 추가 발견 — 오염은 비용 문제이기도 하다

Test A(정상 인증, 사용자 설치본 **243개** skill 로드) 의 사소한 1회 dispatch 비용은 **$0.5409** 였다. 프롬프트는 `/ywc-spike-sentinel` 한 줄, 응답은 17자다. 비용의 대부분은 243개 skill description 이 매 호출 컨텍스트에 실리는 데서 온다.

spec 의 NFR1 은 이 수치를 반영해야 한다. 6회 paired trial × 2 arm 이면 **케이스 1개당 약 $6.5** 이며, 이는 격리 없이 측정할 때의 값이다. **격리는 정확성 장치일 뿐 아니라 비용 절감 장치다** — 임시 config dir 은 컨텍스트에서 243개 description 을 걷어낸다.

(참고: spec 원본은 오염원을 "40여 개" 로 적었다. 실측은 243개다. `~/.claude/skills` 에는 이 toolkit 외 다수 플러그인 skill 이 설치되어 있다.)

## 확정된 계약

| 항목 | 결정 |
|---|---|
| 격리 수단 | 후보 2개 — (a) `CLAUDE_CONFIG_DIR=<임시 디렉터리>` + 프로젝트 로컬 `.claude/skills/<target>`, (b) `--bare`. **(b) 는 구독 인증을 배제한다** |
| 격리 등급 | `best-effort, credential-gated` — 호스트 파일시스템 비관측성은 **주장하지 않는다** |
| 발동 방식 | `claude -p "/<skill-name> <prompt>"` (두 후보 모두에서 `/name` 해석 유지) |
| 판정 근거 | `--output-format json` 의 `result` 에 대한 outcome 검사. `activation_observability: unavailable` |
| ablation without-arm | `--disable-slash-commands` (자연어 프롬프트와 함께 사용) |
| 비격리 실행 | **가능하며 이미 검증됨** — 구독 인증으로 동작($0.5409/dispatch). API key 불필요 |
| 인증 | **미해결이자 이번 spike 의 핵심 트레이드오프** — 격리를 택하면 구독을 잃는다 |

## 남은 차단 요소: 격리 대 구독

Codex spec Iteration 2 의 선택지에 `--bare` 발견을 반영해 재정리한다. 이것은 핸드오프 선택이 아니라 **노선 선택**이다.

| 노선 | 격리 | 구독 사용 | 상태 | 비고 |
|---|---|---|---|---|
| **N1. 비격리 + ablation 귀속** | ✗ | **○** | **검증 완료** | 지금 당장 가능. 243개 skill 이 함께 로드되어 dispatch 당 $0.54. 귀속은 단일 실행이 아니라 with/without 차이로만 주장 (spec Open Question 1 의 예상 답) |
| **N2. `setup-token` + 격리** | ○ | **○(추정)** | **미검증 — 최우선 확인 대상** | 성립하면 최선. 토큰이 임시 config dir / `--bare` 에서 통하는지가 관건 |
| **N3. `ANTHROPIC_API_KEY` + `--bare`** | ○ | ✗ | 미검증 (키 부재) | 별도 과금 채널 발생. 구독을 쓰지 못함 |
| **N4. 자격증명 파일 복사** | ○ | ○ | **수행하지 않음** | `/tmp` 에 OAuth 토큰 노출 — 보안상 부적절 |

**권장 순서: N2 → (실패 시) N1.** N3 는 CI 에서 구독과 무관하게 돌려야 할 이유가 생겼을 때만 고려한다.

## 다음 회차 spike 가 닫아야 할 것

1. **(최우선)** `claude setup-token` 이 발급하는 토큰이 임시 config dir 또는 `--bare` 에서 통하는가 — 노선 N2 의 성패. 통하면 격리와 구독을 동시에 얻는다.
2. 인증이 확보되면, 격리가 **실제로** 243개 skill 을 억제하는가. 판정 지표 두 가지: (a) user-level 전용 skill 의 `/name` 이 `Unknown command` 가 되는가, (b) **dispatch 비용이 $0.54 대비 유의하게 떨어지는가**.
3. description 기반 자동 활성화가 `-p` 에서 동작하는가. (`--bare` 는 skill 이 `/name` 으로 해석된다고만 명시할 뿐 자동 활성화는 언급하지 않는다 — 별도 확인 필요.)

1·2 가 닫히면 등급은 `isolated` 로 올라가고 spec 의 `Root cause identified` 는 58 → 85+ 로 이동한다. **N1(비격리 + ablation) 로 가기로 결정하는 것도 유효한 종결**이며, 그 경우 등급은 `best-effort` 로 확정되고 귀속 주장 범위를 좁히는 것으로 spec 을 닫는다.
