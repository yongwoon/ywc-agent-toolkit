## Global Constraints

- Codex skills live in `codex/skills/<skill-name>/`; custom agents live in `codex/agents/<agent-name>.toml`.
- Every changed Codex skill must keep `SKILL.md`, Tier 1 localized READMEs, and `agents/openai.yaml`; `bash scripts/validate.sh` is the required pre-PR validation command.
- Codex `SKILL.md` frontmatter contains only `name:` and `description:`.
- `codex/skills/` is the source of truth; `plugins/ywc-agent-toolkit/skills/` is generated by `bash scripts/sync-codex-plugin.sh` and must not be edited first.
- Codex agent TOML must retain `gpt-5.6-terra`, medium/high reasoning effort, and an explicit sandbox mode; read-only is the default unless the agent has a deliberately bounded edit contract. Update the existing Codex-agent validation rule so only the two named, bounded workers may use `workspace-write`; all other agents remain `read-only`.

## Purpose

PR #231 adds an opt-in Quality Gate Contract: executors consume caller-approved complexity and mutation evidence through bounded Cleaner then Hardener workers. PR #232 fixes critical operational details—state aggregation, enforced/advisory routing, immutable command binding, and evidence-boundary completeness—that prevent an unrun or degraded gate from being reported as a clean pass.

This repository already has strong task verification, review, ownership, architecture-packet, and specialist-agent contracts, but it has no shared quality-gate vocabulary, bounded write agents, or executor bridge for complexity/mutation evidence. Port the relevant Codex-facing behavior without requiring projects to install CRAP or mutation tooling and without changing the Claude Code bundle.

## Outcome Oracle

- **Target:** Codex planning, task-generation, execution, and implementation-review surfaces can carry an opt-in Quality Gate Contract that dispatches only task-bounded Cleaner and Hardener agents while preserving the current no-contract workflow.
- **Quality threshold:** The source and generated Codex marketplace package define the same contract; only a valid declared packet can enable a gate; Cleaner and Hardener have disjoint production versus test/fixture write boundaries; and gate state/evidence is aggregated without raw commands or an earlier concern being masked.
- **Evidence required:** Passing Codex contract evals for each changed skill/agent, the targeted agent-install test, `bash scripts/sync-codex-plugin.sh`, `bash scripts/validate.sh`, and targeted repository searches for the required boundaries and references.
- **Stop condition:** Hand off for task generation only when all AC1–AC7 have direct passing evidence, the generated package is current, and no contract-evaluation result reports a missing packet, boundary violation, fabricated command, unrun-gate pass, or unresolved enforced failure.

## Scope

- Add a shared Codex quality-gate reference defining contract states, evidence fields, threshold semantics, and the non-passing sentinel for an unrun gate.
- Add task-bounded, write-enabled `ywc-complexity-cleaner` and `ywc-test-hardener` agents with disjoint production-code versus test/fixture edit boundaries.
- Extend `ywc-plan`, `ywc-task-generator`, and `ywc-project-scaffold` so a project can declare, carry, or explicitly omit the contract without fabricated commands.
- Insert conditional Cleaner → Hardener gates in both Codex executors and make `ywc-impl-review` consume only sanitized gate evidence.
- Add/extend skill and agent contract evals; sync the generated Codex marketplace package and validate installation/catalog behavior.

## Out of Scope

- Changing `claude-code/**`, even where PR #231 contains a Claude Code counterpart.
- Adding CRAP, mutation-testing, YAML, or any other runtime dependency to user projects; a project supplies its own approved command identities and evidence.
- Editing generic evaluation-harness code or implementing PR #233's `fenced_yaml_shape` assertion. That change is outside `codex/skills` and `codex/agents`; assess it separately if the repository adopts a richer output-eval harness.
- Automatically treating surviving mutations as equivalent, modifying production code from the Hardener, modifying tests from the Cleaner, or granting either worker staging, commit, push, PR, merge, or delivery authority.
- Making gates mandatory for a project that has no declared contract.

## Quality Gate Contract

### Canonical packet

The shared reference owns the exact field names and allowed values. A present contract must contain only bounded metadata:

- `contract_state`: `report-only`, `advisory`, `enforced`, `NEEDS_CONTEXT`, or `N/A — no quality gate contract`.
- Exact task Ownership paths and changed-function/test-or-fixture paths.
- Approved immutable command identifiers plus digests, never raw executable command text.
- Sanitized evidence artifact paths, threshold values, attempt cap, and a residual-survivor list where applicable.
- Complexity threshold (caller-approved maximum CRAP, ordinarily in the 6–8 range) and mutation target (caller-approved score, ordinarily at least 90%).

`N/A — no quality gate contract` retains today’s workflow. `report-only` records evidence without dispatching write agents. `advisory` may surface `DONE_WITH_CONCERNS`; `enforced` turns unavailable authorized tools, threshold misses, or capped residual survivors into `BLOCKED`. Missing boundary, authorization, digest, or required packet fields is `NEEDS_CONTEXT`, never an inferred pass.

### Interfaces

| Producer | Produces | Consumer | Consumes |
|---|---|---|---|
| `ywc-plan` / `ywc-project-scaffold` | Contract declaration or exact `N/A` sentinel | `ywc-task-generator` | State, thresholds, enforcement, and command-identity requirements; no executable text. |
| `ywc-task-generator` | Per-task Quality Gate Contract packet plus exact Ownership | Executors | Bounded paths, approved IDs/digests, evidence paths, attempt cap, and state. |
| Cleaner | Production-only result: status, pre/post test evidence, max CRAP, changed paths | Hardener/executor | Cleaner status and sanitized evidence; Hardener is never dispatched after a disallowed Cleaner result. |
| Hardener | Test-only result: status, score, attempts, residual survivors, changed paths | Executor/reviewer | Sanitized terminal evidence; no equivalence judgment. |
| Executor | Aggregate status with evidence boundary | `ywc-impl-review` / completion report | `BLOCKED > NEEDS_CONTEXT > DONE_WITH_CONCERNS > DONE` precedence and retained residual concerns. |

## Acceptance Criteria

- [ ] **AC1 — Backward-compatible absence**: When a plan, scaffold, or task has no declared Quality Gate Contract, the system records `N/A — no quality gate contract`, invokes neither worker, and preserves the current executor/review path, observable in contract evals.
- [ ] **AC2 — Safe task metadata**: When task generation receives an eligible declared contract, it emits exact Ownership, state, thresholds, approved command IDs/digests, and sanitized evidence paths, observable with no raw command text, transcript, full diff, or placeholder packet in generated task metadata.
- [ ] **AC3 — Bounded Cleaner**: When an eligible task’s approved complexity evidence exceeds its threshold, the Cleaner changes only task-owned production paths, runs the approved baseline test before and after, and never stages or delivers changes, observable in its agent contract evals.
- [ ] **AC4 — Bounded Hardener**: When Cleaner permits dispatch and mutation survivors remain, the Hardener changes only task-owned tests/fixtures, makes at most three approved attempts, and reports every residual survivor without claiming equivalence, observable in its agent contract evals.
- [ ] **AC5 — Status correctness**: When either gate returns a concern, unavailable advisory tool, missing packet field, or enforced failure, executor output respectively retains `DONE_WITH_CONCERNS`, returns `NEEDS_CONTEXT`, or blocks; a later `DONE` never masks an earlier concern, observable in sequential and parallel evals.
- [ ] **AC6 — Review evidence integrity**: When implementation review receives quality-gate data, it consumes only the sanitized evidence boundary and caps/downgrades confidence when required evidence is absent, observable in `ywc-impl-review` evals without raw commands, output, secrets, or full diff.
- [ ] **AC7 — Distribution validation**: When all Codex changes are complete, the source bundle and generated marketplace package match, the catalog lists both workers, and `bash scripts/validate.sh`, Codex contract evals, and targeted agent-install tests pass.

## Functional Requirements

### FR-1: Shared contract and planning declaration

Create `codex/skills/references/quality-gates.md` as the single source for states, packet fields, evidence redaction, dispatch eligibility, thresholds, retry/cap rules, and status aggregation. Update `ywc-plan` and its spec template to require a `Quality Gate Contract` section (or exact N/A sentinel) and explicit module boundaries for Medium/Large specs. Update `ywc-project-scaffold` to propose an advisory contract seed only when requested; it must never invent a command or create a project file.

### FR-2: Task-owned interface propagation

Update `ywc-task-generator` and its README/task templates to include a conditional Quality Gate Contract/Owned Interface section. It must bind task ownership and command identities/digests to every downstream worker; when no valid declaration exists, omit the entire conditional block rather than emitting placeholders.

### FR-3: Two bounded write agents

Add `ywc-complexity-cleaner` and `ywc-test-hardener` TOML files. Both require all packet inputs, start with canonical terminal status, redact raw execution data, and never stage/commit/push/create PRs/merge/deliver. Cleaner owns only task production code and behavior-preserving complexity reduction; Hardener owns only task tests/fixtures and mutation-survivor assertion hardening. Both use `workspace-write` and medium reasoning; update the existing `scripts/validate.sh` Codex-agent sandbox check to allow `workspace-write` only for these two exact filenames and require `read-only` for every other Codex agent. The installer compatibility rewrite remains responsible for legacy model fallback.

### FR-4: Sequential executor gate

After normal Step 4 verification and before optional implementation review/delivery, resolve the conditional task packet. Dispatch Cleaner before Hardener only when contract state and Cleaner status permit it. Aggregate worker results with `BLOCKED > NEEDS_CONTEXT > DONE_WITH_CONCERNS > DONE`, carry sanitized evidence and residuals to the Completion Report, and retain the existing lifecycle unchanged for N/A/report-only cases.

### FR-5: Parallel executor gate

Apply the bounded Cleaner to each eligible completed task before its wave delivery and run the Hardener only after the Cleaner result permits it. Preserve task worktree/branch for blocked outcomes, perform mutation aggregation at a wave boundary, and use the same precedence so an advisory concern cannot be overwritten by another worker’s `DONE`.

### FR-6: Review and evaluation coverage

Teach `ywc-impl-review`’s QA reference and report rules how to recognize a valid quality-gate evidence boundary, residual survivors, unavailable tools, and missing evidence. Add positive, missing-boundary, out-of-ownership, unavailable-tool, residual-survivor, status-aggregation, and no-contract evals to the affected skill/agent eval files.

### FR-7: Codex catalog and generated-package release

Update the Codex agent README/catalog and only the necessary Codex skill READMEs. Regenerate `plugins/ywc-agent-toolkit/skills/` from source, verify it is byte-for-byte current through existing validation, and add a targeted installer assertion for both new agents if the current agent-install fixture cannot already enumerate them.

## Edge Cases

- An eligible project lacks an approved command identity, digest, exact Ownership, or evidence path: return `NEEDS_CONTEXT`; do not dispatch a worker.
- A project has a contract but its tool is unavailable: advisory returns `DONE_WITH_CONCERNS`; enforced returns `BLOCKED`; report-only records the gap without mutation.
- Cleaner returns `DONE_WITH_CONCERNS`: do not let a later Hardener `DONE` erase it; aggregate the stronger status.
- Cleaner is `BLOCKED` or `NEEDS_CONTEXT`: do not dispatch Hardener.
- Hardener reaches its three-attempt cap with survivors: advisory preserves them as concerns; enforced blocks; neither labels a survivor equivalent.
- A requested edit lies outside task Ownership or crosses production/test boundary: worker returns `NEEDS_CONTEXT` and performs no edit.
- A task has no quality contract: no empty conditional packet appears and no quality-gate agent is selected.

## Risks and Rollback

- **Risk:** Adding mandatory-looking prose accidentally changes no-contract behavior. **Mitigation:** require the exact N/A sentinel and no-dispatch evals in every consumer.
- **Risk:** Disparate state mappings hide an advisory concern. **Mitigation:** one shared precedence table plus sequential/parallel aggregation fixtures.
- **Risk:** Write agents broaden the executor’s authority. **Mitigation:** exact Ownership input, disjoint edit domains, immutable identifiers/digests, and explicit no-delivery rules.
- **Rollback:** Revert the contract consumer changes and remove the two agent entries together; the pre-existing task verification/review lifecycle remains intact. Regenerate the marketplace package after any source revert.
