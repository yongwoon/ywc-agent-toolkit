# Extend ZH/ES Language Support Across Language-Aware Skills

> Status: Draft
> Scale: Medium
> Created: 2026-07-02
> Author: Codex
> Spec Reference: N/A - standalone skill-maintenance plan

## Purpose

The Codex `ywc-project-docs` skill now supports Korean, Japanese, English, Simplified Chinese, and Spanish. Other Codex language-aware skills still expose Korean/Japanese/English-only contracts or pass-through PR language handling, so users can request `zh` or `es` in one skill and lose that intent downstream.

This change expands the same `zh` and `es` language support model to the remaining Codex language-aware skills while preserving each tool's existing scope and the `codex/skills` source-of-truth packaging flow.

## Scope

- Add explicit Simplified Chinese and Spanish support to active output-language skills other than `ywc-project-docs`:
  - `ywc-spec-writer`
  - `ywc-task-generator`
  - `ywc-gen-testcase`
- Add `zh` and `es` as accepted PR/report language codes to workflow skills that pass or infer language:
  - `ywc-create-pr`
  - `ywc-finish-branch`
  - `ywc-sequential-executor`
  - `ywc-parallel-executor`
  - `ywc-agentic`
  - `ywc-handle-pr-reviews`
- Update only `/Users/yongwoon.kim/Desktop/yongwoon/source/private/ywc-agent-toolkit/codex/skills/**` source files.
- Update Codex `agents/openai.yaml`, eval fixtures, and README locale files where user-facing options or examples mention supported languages.
- Run `bash scripts/sync-codex-plugin.sh` after Codex source edits so `plugins/ywc-agent-toolkit/skills/` remains generated from `codex/skills/`.
- Validate the final source with per-skill validation where available and `bash scripts/validate.sh`.

## Out of Scope

- Do not modify `ywc-project-docs`; it is the reference implementation for this work.
- Do not modify `claude-code/**`; this plan is Codex-only.
- Do not add a new `--lang` contract to Codex `ywc-spec-ready`; it is not currently a language-output skill in `codex/skills`.
- Do not add new translation infrastructure or make `README.zh.md` / `README.es.md` mandatory in `scripts/validate.sh`.
- Do not translate all historical README prose from scratch unless the file's supported-language contract becomes stale.
- Do not alter unrelated skill behavior, task sequencing, PR merge policy, or bot-review policy.
- Do not change install paths, plugin manifest metadata, release version, or changelog unless the release workflow explicitly requires it later.

## Functional Requirements

### FR-1: Establish a Canonical Language Code Policy

- Use the `ywc-project-docs` five-language model as the reference:
  - Korean
  - Japanese
  - English
  - Chinese (Simplified)
  - Spanish
- Preserve each skill's existing Korean code:
  - Skills already using `ko` keep `ko`.
  - `ywc-project-docs` remains unchanged with `kr`.
- Add aliases consistently:
  - `zh`, `chinese`, `中文`, `Chinese`, `Chinese (Simplified)`
  - `es`, `spanish`, `espanol`, `español`, `Spanish`
- State that body prose is localized but command names, file paths, YAML keys, JSON keys, code blocks, and technical terms remain English unless the existing skill says otherwise.

### FR-2: Update Content-Output Skills

#### `ywc-spec-writer`

- Update Codex `SKILL.md` descriptions and argument table from `ko|ja|en` to `ko|ja|en|zh|es`.
- Update default-language behavior without changing the existing default of Korean (`ko`).
- Extend `references/language-policy.md` with Chinese and Spanish body-prose rules and technical-term examples.
- Update document templates or checklist text that says the spec language must match only `ko|ja|en`.
- Update README locale set and Codex `agents/openai.yaml`.
- Add Codex evals for `--lang zh` and `--lang es`.

#### `ywc-task-generator`

- Update Codex `SKILL.md` from `korean|japanese|english` to include `chinese|spanish` plus code aliases.
- Update inference prompts and examples to include Chinese and Spanish.
- Extend `references/language-policy.md` with Chinese and Spanish rules.
- Preserve existing hard gates for DB migration separation, library separation, and phase boundaries.

#### `ywc-gen-testcase`

## Edge Cases

- **Mixed-language input**: If a user writes "PR Spanish로 작성" or "中文 task docs", the skill should infer the requested target language and not default to English.
- **Ambiguous `chinese` request**: Treat `zh` / `chinese` as Simplified Chinese unless the user explicitly asks for another Chinese locale.
- **Accent-less Spanish alias**: Accept both `espanol` and `español` in user-provided language text.
- **Existing Korean code mismatch**: Do not force `kr` into skills that already use `ko`; backward compatibility matters more than code uniformity.
- **Machine-readable sections**: YAML, JSON, command examples, file names, task IDs, PR numbers, and frontmatter keys remain English or existing machine syntax regardless of prose language.
- **Generated plugin diff**: Plugin mirror may differ from source in rewritten installed paths due to `scripts/sync-codex-plugin.sh`; verify via validation rather than byte-identical expectations.
