## Purpose

PR #223 strengthens review-artifact handling in its Codex bundle with behavior-level tests for Nitpick mapping and review-submission suppression, plus related parser tests in the Claude bundle. This repository's current Codex implementation has no Nitpick parser or Nitpick artifact path, so the parser-specific changes cannot be copied directly. The applicable improvement is to add end-to-end fixture tests around the current Codex artifact collector before changing its behavior.

## Scope

- Add a Python `unittest` harness for the current `codex/skills/ywc-handle-pr-reviews/scripts/fetch-pr-review-artifacts.sh`.
- Execute the shipped Bash script against deterministic fake `gh` responses and JSON fixtures, so tests exercise the actual embedded `jq` program rather than a separately invented implementation.
- Cover the current contract for:
  - review-thread normalization and latest unresolved reviewer comment selection;
  - PR-level addressed-marker suppression;
  - review-submission filtering, including self-authored and already-addressed submissions;
  - failed-versus-successful status-check normalization;
  - merge-readiness artifact emission for non-clean states.
- Mirror the source test additions into the generated marketplace package with `bash scripts/sync-codex-plugin.sh`.

## Out of Scope

- Porting the Claude-only Nitpick parser tests or adding a new Codex Nitpick parser. The current Codex tree has no `extract-coderabbit-nitpicks.py`, Nitpick fixture, or `raw_fallback` producer.
- Adding the PR #223 `raw_fallback` user-confirmation rule to Codex. It becomes applicable only when Codex emits parsed Nitpick artifacts with that status.
- Changing the normalized artifact schema, marker format, GitHub API calls, review classification policy, or reply behavior.
- Refactoring the embedded `jq` program into a separate production file solely to make it testable.
- Editing the generated marketplace copy independently of the source tree.

## Acceptance Criteria

- [ ] **AC1 — Actual collector execution**: The new test harness invokes the shipped `fetch-pr-review-artifacts.sh` with a fake `gh` executable and fixture JSON; it does not only test a copied or reimplemented `jq` filter.
- [ ] **AC2 — Review-thread contract**: Fixtures prove that an unanswered reviewer comment is emitted, a self-response suppresses an older comment, and a newer reviewer comment reopens the artifact.
- [ ] **AC3 — Marker suppression**: A PR-level addressed marker suppresses only the matching fingerprint; unrelated artifacts remain in the output.
- [ ] **AC4 — Review-submission contract**: Non-empty external `COMMENTED` and `CHANGES_REQUESTED` reviews are emitted with the expected normalized fields; approvals, empty bodies, and self-authored reviews are excluded.
- [ ] **AC5 — Health gates**: Failed/pending status checks produce `status_check` artifacts, successful/skipped/neutral checks do not, and non-clean merge states produce `merge_readiness` while clean states do not.
- [ ] **AC6 — Deterministic local validation**: The focused Python test command passes, `bash -n` passes for the collector, and `bash scripts/validate.sh` passes.
- [ ] **AC7 — Bundle parity**: The source test file and generated marketplace copy are identical after `bash scripts/sync-codex-plugin.sh`.
- [ ] **AC8 — Scope boundary**: No Codex Nitpick parser or `raw_fallback` behavior is introduced by this change; the plan records that PR #223's parser-specific portion remains deferred until such a producer exists.

## Functional Requirements

### FR-1: Isolated collector test harness

Create `codex/skills/ywc-handle-pr-reviews/scripts/test_fetch_pr_review_artifacts.py`. The harness must create temporary fixture files and a fake `gh` command that responds to the exact `api user`, review endpoint, and `pr view` calls made by the collector. Tests must parse stdout as JSON and clean up all temporary state.

### FR-2: Preserve the current normalized contract

Tests must assert artifact type, fingerprint, reply API, body, path/line, user, state, and relevant health fields where the current script emits them. The implementation must not loosen or alter the existing contract merely to accommodate the tests.

### FR-3: Test marker and liveness transitions

Fixtures must cover the complement of the current artifact paths: unresolved versus addressed review threads, PR comments, review submissions, status checks, and merge readiness. Each test should identify which artifact is expected to be emitted or suppressed and why.

### FR-4: Keep Nitpick scope explicit

The test module and plan documentation must state that `raw_fallback`, Nitpick fingerprint mapping, and review suppression by Nitpick review ID are not current Codex behaviors. If a future implementation adds that path, it requires a separate plan or amendment with parser fixtures and the user-confirmation guardrail from PR #223.

## Non-Functional Requirements

| Category | Requirement |
|---|---|
| Determinism | Tests must not call GitHub, require `gh` authentication, or depend on wall-clock time. |
| Portability | Use Python standard library only; use portable Bash-compatible fake commands and avoid shell-specific test assumptions beyond the repository's zsh invocation of Bash scripts. |
| Maintainability | Fixtures should be small and named by behavior; assertions should fail with the artifact type/fingerprint that diverged. |
| Safety | Tests must not write to the user's real Codex or Claude skill directories. |

## Edge Cases

- **No issue comments**: The collector must still emit unresolved review artifacts and must not fail marker extraction.
- **Multiple comments in one thread**: The latest reviewer comment after the latest self-response is authoritative.
- **Legacy marker without fingerprint**: Preserve the current thread marker behavior and test it separately from fingerprint-based PR-level suppression.
- **Empty review body**: Exclude an empty review unless its state is a qualifying review state and the current contract explicitly says otherwise; encode the observed current behavior in the assertion.
- **Missing optional health fields**: Verify the current fallback to `UNKNOWN` for status/merge fields rather than inventing a new normalization rule.
- **Missing local `gh` authentication**: Keep the existing exit-3 behavior covered by one focused failure test if practical; do not weaken production error handling to make setup easier.
