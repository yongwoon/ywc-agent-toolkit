## Functional Requirements

> ⚠️ SUPERSEDED in part by Iteration 1 — map creation/resume and ticket-state

### Amendment A — Deterministic Wayfinder map and ticket contract

`ywc-wayfinder` accepts a destination for a new map, or `--resume <map-path>`
for an existing map. New maps derive a lowercase kebab-case `<slug>` and write
only `docs/ywc-plans/<slug>-wayfinder.md`; a collision returns `NEEDS_CONTEXT`
and never overwrites a map. Resume rejects absolute paths, traversal, missing
maps, and maps outside `docs/ywc-plans/`.

Each map contains canonical ticket IDs and these `Local Status` values:
`open`, `in_progress`, `resolved`, `deferred`, and `blocked`. A resume requires
`--ticket <ticket-id>` when more than one ticket is `open` or `in_progress`;
otherwise the single eligible ticket is selected. A missing/non-eligible ticket
returns `NEEDS_CONTEXT` without changing the map. Only one ticket may move to
`in_progress` in a session. A ticket becomes `resolved` only with Resolution
Evidence and Next Context Pointer; unresolved work remains under `Not Yet
Specified` or Fog rather than being treated as a decision.

The map template records `Created At` / `Updated At`, Destination, Notes,
Decisions So Far, Open Decision Tickets, Not Yet Specified, Fog, and Out of
Scope. Optional tracker observations contain URL/ID/status/observed-at only;
they never modify an external tracker or `Local Status`.

### Amendment B — Preview approval is a replay-safe write gate

`ywc-task-generator` gains `--non-interactive`, `--preview-path <path>`, and
`--approve-preview <sha256>`. After decomposition and before any task or
dependency-graph write, it writes a canonical preview at
`docs/ywc-plans/<spec-slug>.task-decomposition-preview.md` by default (or at a
validated repository-relative `--preview-path` under `docs/ywc-plans/`). The
preview has `Preview Revision`, `Created At`, `Spec Path`, `Tasks Dir`, selected
language/mode, the seven AC3 columns, and a SHA-256 digest over its canonical
content.

Interactive callers see the preview and must approve its displayed digest.
Rejection writes no `<tasks-dir>/` task directory or dependency graph; it
appends the rejection reason and timestamp to the preview, recomputes a new
revision/digest after requested changes, and requires new approval. The
generator refuses a stale/mismatched digest.

Non-interactive generation is valid only when all of the following are true:
`--non-interactive`, resolved `--lang`, explicit `--mode`, and
`--approve-preview <current-sha256>` are present. Otherwise it returns
`NEEDS_CONTEXT` before task generation. `ywc-agentic` must invoke the
generator with `--non-interactive --mode llm --lang <resolved-lang>` and the
current digest; it records preview path/revision/digest, source spec path,
full invocation, approval mode, and UTC timestamp in its existing append-only
run log. Caller identity, environment variables, and implicit upstream state
cannot authorize a write.

### Amendment C — Optional-spec implementation review

Make `ywc-impl-review --spec <path>` optional while retaining exactly one code
target (`--code`, `--git-range`, or `--working-tree`) as required. A supplied
missing or unreadable spec remains `BLOCKED`; omission of `--spec` is valid.
Without a spec, all five review lanes run and aggregate output contains exactly
`## Spec Traceability` followed by `No spec available`; it emits no acceptance
criterion rows or criterion statuses. `Not Verifiable` is used only when a
specific acceptance criterion exists but lacks admissible evidence.

With a valid spec, the matrix has `Criterion`, `Status`, `Evidence`, and
`Scope-creep note` columns. Evidence must be a `file:line`, named test/output,
or command output. Update the argument table, output format (including HTML
parity), completion rules, all relevant callers, and evals for valid omitted
spec, invalid supplied spec, and evidence-free criteria.

### Amendment H — Two-phase autonomous preview and terminal map behavior

`--preview-only` is the sole bootstrap exception to Amendment B's approval
requirement. It accepts resolved `--lang`, explicit `--mode`, `--tasks-dir`,
and optional `--preview-path`; it decomposes in memory, writes/updates only the
canonical preview, and returns `{preview_path, preview_revision, sha256}`. It
does not require `--non-interactive`, does not accept `--approve-preview`, and
never creates `<tasks-dir>/`, task directories, or a dependency graph.

`ywc-agentic` performs two calls: first
`ywc-task-generator --preview-only --tasks-dir <tasks-dir> --mode llm --lang
<resolved-lang>`, then verifies the returned path/revision/digest and appends
that exact result with UTC timestamp to its run log. Second it invokes
`ywc-task-generator --non-interactive --tasks-dir <tasks-dir> --mode llm
--lang <resolved-lang> --approve-preview <sha256>`. The second call consumes
the persisted canonical preview without re-decomposing. It rejects missing,
stale, mismatched, or input-incompatible previews with `NEEDS_CONTEXT` and
writes no task artifacts. Add fixtures for preview-only → valid consume, stale
digest, missing preview, and attempted direct non-interactive bypass.

On Wayfinder resume with no `open` or `in_progress` ticket, the skill performs
no write. If all tickets are `resolved`, it returns `DONE` with the recorded
`ywc-plan`/research handoff. If one or more tickets are `deferred` or
`blocked`, it returns `NEEDS_CONTEXT` with their IDs and blocking context. Add
fixtures for both terminal-map outcomes.

### Amendment I — Research overwrite confirmation

Add `--overwrite` to `ywc-tech-research` arguments. It does not itself confirm
