## Purpose

`develop-with-llm` PR #132, #133, #134, and #140 contain workflow-contract fixes that should be ported into this repository's Codex bundle. The target repository has a different layout (`codex/skills/` as source of truth plus generated `plugins/ywc-agent-toolkit/skills/`), so implementation must be a selective Codex port rather than a blind copy from `tools/codex-skill/`.

The user wants all applicable changes handled in one branch. This spec groups the work into one Medium-size branch with ordered phases: active skill contracts, helper script / metadata, eval coverage, generated plugin sync, and validation.

## Scope

- Port PR #132's `ywc-plan` Medium/Large handoff change: offer `ywc-spec-ready` as an opt-in shortcut after drafting a spec, and update the `ywc-plan` README locale set accordingly.
- Port PR #133's PR-health model into `ywc-handle-pr-reviews`, including unresolved review artifacts, failed CI/status checks, and merge-readiness blockers even when no comments exist.
- Port PR #133's executor call-site changes so sequential/parallel aggregate and draft flows invoke `ywc-handle-pr-reviews` as the canonical PR health sweep, not only when bot comments exist.
- Port PR #134's Codex-applicable skill improvements:
  - `ywc-create-pr` mandatory author self-review gate before filing/updating a PR.
  - `ywc-spec-validate --tasks <dir>` cross-artifact consistency pass.
  - `ywc-onboard-repo` agent-context pre-check for existing `AGENTS.md`, `.cursorrules`, Cursor rules, and Copilot instructions.
  - long-run compaction guidance for `ywc-agentic` and `ywc-sequential-executor`.
- Port PR #140's active Codex parity fixes:
  - stale `ywc-project-docs-ja` / `ywc-project-docs-kr` shared reference removal.
  - internal repository URL replacement in `ywc-gen-testcase` active docs/examples.
  - `ywc-spec-validate` Confidence Gate status mapping correction.
  - Codex eval fixture additions for `ywc-project-docs` and `ywc-project-scaffold`.
- Sync generated plugin package under `plugins/ywc-agent-toolkit/skills/` after source `codex/skills/` edits.
- Update root release metadata only if the final source changes require it according to this repository's current release process.

## Out of Scope

- Do not modify `claude-code/**`; this is Codex-only.
- Do not introduce source repo paths such as `tools/codex-skill/**` into skill bodies.
- Do not port `docs/studies/llm/**` research notes from PR #134 into this repository unless a separate docs request is made.
- Do not change provider-specific model names in Codex skills unless current Codex text actually contains stale provider-specific wording.
- Do not redesign the eval harness or migrate fixtures to a new schema.
- Do not split into multiple branches; task sequencing should assume one branch.
