# Codex skill executable-resolution hardening

> Status: Draft
> Scale: Medium
> Created: 2026-09-19
> Spec Reference: `develop-with-llm` PR #240 and issue #242 / PR #244

## Global Constraints

- Codex skills are the source of truth in `codex/skills/`; the marketplace bundle under `plugins/ywc-agent-toolkit/skills/` is generated by `bash scripts/sync-codex-plugin.sh` and must not be edited first (`codex/AGENTS.md`).
- Codex `SKILL.md` frontmatter contains only `name` and `description`; each skill retains Tier 1 README files and `agents/openai.yaml` (`AGENTS.md`, `CLAUDE.md`).
- `bash scripts/validate.sh` is the repository's required pre-PR structural validation command (`AGENTS.md`).
- Codex custom agents are TOML definitions under `codex/agents/`; read-only agents must retain their inline/no-artifact output contract (`scripts/validate.sh:542-596`).

## Purpose

PR #240's evidence-collection extraction is not directly portable: this bundle has no corresponding Codex shared-script package or Evidence Snapshot v1 producer. Its security follow-up, issue #242 (fixed in sibling PR #244), is directly applicable: a skill must never fall back from a missing installed executable to a same-named path controlled by the target repository.

The current bundle has 18 such fallback clauses across ten Codex source files, plus two direct target-relative test-script executions. The change will establish one trusted executable-resolution contract, migrate that closed set, and prove that a hostile lookalike target repository cannot be executed.

**Outcome Oracle:** Target — every Codex skill invocation selects only an installed bundle executable or an explicitly authorized development-source executable. Quality threshold — all 20 executable-selection sites reject an untrusted target path without side effects, while the current installed and interpreter-invoked flows remain usable. Evidence required — the shipped resolver's hostile-target regression, its non-executable interpreter fixture, the complement check, `scripts/check-codex-agent-evals.sh`, plugin sync, and `bash scripts/validate.sh`. Stop condition — validation reports zero unsafe executable-selection sites and all required checks pass.

## Scope

- Add a Codex-only shared resolver and reference that define the installed-first, explicitly opted-in bundle-development fallback and `BLOCKED` behavior.
- Migrate every current target-relative executable fallback or direct command in the closed set below to that contract.
- Add a regression harness and a closure check so future fallback clauses cannot silently reintroduce target-repository execution.
- Synchronize the generated marketplace skill package after source changes.

## Out of Scope

- Porting PR #240's shared evidence collectors or Evidence Snapshot v1 infrastructure. No Codex source here currently produces or consumes that contract, so adding it would be speculative.
- Claude Code skills and agents; they are a separately maintained surface.
- Changing `codex/agents/*.toml`. The agents do not resolve or execute bundle scripts; their existing bounded-packet and inline/no-artifact contracts remain unchanged.
- Altering an installed bundle's normal behavior when its executable exists, or introducing runtime dependencies.

## Acceptance Criteria

- [ ] **AC1 — Installed execution is unchanged:** When every referenced executable exists under `${CODEX_HOME:-$HOME/.codex}/skills`, each migrated skill/script invokes that installed executable with its current arguments.
- [ ] **AC2 — Development fallback requires two explicit trust signals:** When an installed executable is absent, source fallback is allowed only if the development opt-in is set and the configured source root resolves to the canonical Git root with this bundle's expected origin/layout identity; the candidate must be a canonical, contained regular file usable by its fixed invocation (`bash`, `python`, `python3`, or direct exec). Direct execution alone requires `+x`.
- [ ] **AC3 — Hostile target is never executed:** When the target repository contains lookalike `codex/skills/...` executables but is not the explicitly verified source root, resolution returns `BLOCKED` before any target executable is invoked.
- [ ] **AC4 — Missing trusted executable is terminal:** When neither an installed executable nor an authorized source executable exists, the affected skill reports `BLOCKED` with the missing installed path and remediation; it does not attempt a target-relative path.
- [ ] **AC5 — Closed-set migration:** A repository-wide complement search identifies all 20 target-relative executable-selection sites in the ten fallback files plus `ywc-task-generator`; each is migrated to the canonical contract or explicitly documented as non-executable text. No command executes or assigns a `codex/skills/...` path relative to the target checkout.
- [ ] **AC6 — Agents remain unaffected:** `scripts/check-codex-agent-evals.sh` and `bash scripts/validate.sh` pass with no required change to `codex/agents/*.toml`.
- [ ] **AC7 — Generated bundle matches source:** After `bash scripts/sync-codex-plugin.sh`, `bash scripts/validate.sh` reports no stale marketplace package.

## Functional Requirements

### FR-1: Define the canonical Codex executable-resolution contract

Create executable `codex/skills/scripts/resolve-bundle-executable.sh`, stdlib-only `codex/skills/scripts/resolve-bundle-executable.py`, and `codex/skills/references/shared-script-resolution.md`, adapting the security model of sibling PR #244 to this repository's layout. The Bash launcher owns installed/source bootstrap selection; the Python resolver owns the testable CLI contract: accept a bundle-relative executable path and fixed invocation kind, print one resolved absolute path on success, or return a nonzero `BLOCKED` diagnostic without invoking the candidate.

1. Resolve the installed executable under `${CODEX_HOME:-$HOME/.codex}/skills/...` first.
2. Permit source fallback only when `YWC_BUNDLE_DEVELOPMENT=1`, `YWC_BUNDLE_SOURCE_ROOT` is an absolute canonical Git root whose `origin` identifies this bundle (`yongwoon/ywc-agent-toolkit`, SSH or HTTPS form) and whose required `codex/skills/` layout exists; then canonicalize the candidate and prove it is contained below that root's `codex/skills/` tree. The explicit opt-in and configured source root are the authority; target-checkout file existence is never authority.
3. Otherwise emit a deterministic `BLOCKED` result naming the expected installed path and the safe development setup; never inspect or execute a target-relative bundle path.
4. For `bash`, `python`, and `python3`, accept a canonical contained regular readable file even when it lacks `+x`; require `+x` only for direct execution. Reject symlinks that resolve outside the authorized root.
5. State that the contract governs executable selection only — it does not authorize changed arguments, shell evaluation, target-repository script discovery, or source fallback by file-existence alone.

Each migrated caller invokes this shipped resolver, rather than reproducing resolver logic in Markdown. The shared reference defines one exact, copyable **resolver-launcher selection block**: first invoke the installed launcher at `${CODEX_HOME:-$HOME/.codex}/skills/scripts/resolve-bundle-executable.sh`; only when it is absent may the block invoke `${YWC_BUNDLE_SOURCE_ROOT}/codex/skills/scripts/resolve-bundle-executable.sh` through fixed `bash`, after the block itself verifies the explicit opt-in, absolute/canonical source root, expected origin/layout identity, and canonical contained launcher path. The launcher invokes the Python resolver through fixed `python3`. Every caller uses that exact block, and the closure validator rejects ad hoc bootstrap variants.

### FR-3: Add security regression and complement validation

Add `tests/codex_executable_resolution_test.py`, run it from the Codex validation section of `scripts/validate.sh`, and make a nonzero test exit increment `ERRORS`. The stdlib-only test invokes both the shipped launcher-selection block and resolver, not a model implementation, and constructs:

- an installed-bundle fixture (normal path succeeds),
- an installed-missing, explicitly authorized launcher-bootstrap fixture (the fixed `bash` launcher path succeeds),
- an explicitly opted-in canonical source-bundle fixture (authorized fallback succeeds),
- an explicitly opted-in canonical source fixture containing non-`+x` shell/Python candidates (fixed-interpreter fallback succeeds),
- a hostile target fixture and a different Git repository with lookalike layout/origin mismatch (resolution fails before either marker can run), and
- missing/untrusted candidates (deterministic `BLOCKED`).

Add a validation check to `scripts/validate.sh` that performs the complement search for target-relative `codex/skills/...` commands or executable assignments. It must fail on a newly introduced unsafe fallback/direct command, distinguish documentation-only examples from executed commands, and prove the 20-site inventory is either migrated or explicitly exempted. Add a `mark-complete.sh` regression that verifies an unresolved compactor does not move a task or create a commit.

## Edge Cases

- `YWC_BUNDLE_DEVELOPMENT=1` but `YWC_BUNDLE_SOURCE_ROOT` is relative, non-Git, symlink-escaping, origin/layout-mismatched, or a different repository: reject it as untrusted.
- The requested source candidate is a symlink outside the canonical source root: reject it; a contained regular non-`+x` file is valid only through its fixed interpreter.
- `CODEX_HOME` is a custom install location: resolve the installed candidate from that value before considering development fallback.
- A caller references two executables in a pipeline: resolve and validate both before running the pipeline; do not run a partial pipeline if either is untrusted/missing.
- Textual documentation uses `codex/skills/...` paths without executing them: the closure validator must not falsely reject it.
- `mark-complete.sh` cannot resolve its compactor: return `BLOCKED` before modifying the task directory or Git index.
