## Global Constraints

- Codex and Claude Code skill roots are **maintained independently, not auto-synced** — a change applied to one root does not propagate to the other; every FR below that touches both roots is two separate edits, never a single shared file (`ywc-agent-toolkit/claude-code/skills/CLAUDE.md` §"Codex-skill: Maintained Independently").
- Every `ywc-*` skill's `description:` frontmatter must read `(ywc) Use when...` and end with `Do not use for ...` anti-triggers; body must keep the `**Announce at start:**` line and a ≥5-row `## Rationalization Defense` table when a skill body is restructured (`claude-code/skills/CLAUDE.md` §"Authoring or Restructuring ywc-* Skills"). This port only inserts new subsections into existing SKILL.md files — it does not add or remove Rationalization Defense rows, since no existing skill's activation semantics change.
- Shared reference docs (bot-polling, PR-conflict, HTML-output, schema) are linked with an explicit `> **Action required**: Read [...]` directive, never inlined or restated by value in a consuming SKILL.md (`claude-code/skills/CLAUDE.md`, multiple sections). The ported `quality-gates.md` follows the same convention.
- Codex `SKILL.md` frontmatter carries only `name` and `description` — no Claude-only fields (root `CLAUDE.md` at `ywc-agent-toolkit/CLAUDE.md` §"Skill Authoring Rules"). Codex custom agents are read-only TOML by default; a write-enabled exception requires "an explicit implementation role and a bounded edit contract" (`codex/agents/README.md` §"작성 Notes").
- README locale set (`README.md` Korean, `README.en.md`, `README.ja.md`, `README.ko.md` Tier 1; `README.zh.md` / `README.es.md` Tier 2 where present) is required for every skill directory (`ywc-agent-toolkit/CLAUDE.md` §"Skill Authoring Rules"). This port touches only `SKILL.md` / `references/*.md` content inside existing skill directories and adds two new `codex/agents/*.toml` files — no new skill directory is created, so no new README set is required. If a caller later decides to promote `ywc-architecture-invariants` to claude-code (see Open Questions), that would be a new skill directory and would trigger this requirement separately.

## Purpose

`develop-with-llm`'s `tools/claude-code/skills/` and `tools/codex-skill/` runtimes merged a "Quality Gate Contract" — CRAP (complexity) and Mutation (test-effectiveness) gates enforced through two new dispatched roles, a Cleaner and a Hardener — across their planning, sequential-execution, parallel-execution, review, and task-generation skills. `ywc-agent-toolkit` is a sibling toolkit distributing the same `ywc-*` skill family to Claude Code and Codex and currently has no equivalent gate contract, no Cleaner/Hardener dispatch procedure, and (on the codex side) no `Owned Interface` task-README field. This spec ports that feature, adapted to this repo's own conventions (existing agent catalog, existing quality-gates absence, independently-maintained codex/claude-code roots) rather than copied verbatim.

## Edge Cases

- **Contract absent for a task/wave**: every inserted gate step must skip cleanly and record the `N/A` sentinel — verified by AC11.
- **Cleaner/Hardener dispatch failure (bounded escalation exhausted)**: never returns `BLOCKED` from the gate step itself; records `gate_state: "not run — dispatch failed"` and routes the task/wave's overall status to `DONE_WITH_CONCERNS`, per `develop-with-llm`'s convention this port preserves verbatim.
- **Mutation survivors remaining after the 3-round cap**: forwarded as a list to the next review step, never adjudicated "equivalent" by the executor or the dispatched agent — equivalent-mutant determination stays a human/reviewer call.
- **CRAP gate says a function is "logically one unit"**: the Rationalization Defense entries in `quality-gate-steps.md` explicitly reject this excuse — decomposition or a registered exclusion-list entry are the only two paths past the gate.
- **A project's `ywc-project-scaffold` (claude-code) is asked to draft an architecture-invariants seed**: since claude-code has no `ywc-architecture-invariants` skill, the claude-code scaffold skill simply does not gain this feature — this is not a runtime edge case to handle defensively, it is a scope boundary (FR-6), and the skill's existing Step 5 output is unaffected.
- **Codex quality-gates.md and claude-code quality-gates.md drift over time**: expected and accepted, per the "maintained independently" constraint — not a defect to reconcile in this port.
- **Partial-port interruption (added iteration 1)**: FR-3, FR-4, FR-5, and FR-10 each insert a `> **Action required**: Read [...]` pointer to `quality-gates.md` (FR-1) — landing any of these before FR-1 exists leaves a dangling reference. Required landing order: FR-1 (both roots' `quality-gates.md`) before FR-3/FR-4/FR-5/FR-10; the codex half of FR-1 specifically before FR-9 (the two new codex agents map their `Status:` output to FR-1's codex enforcement-tier table). FR-2, FR-6, FR-7, FR-8 have no such ordering dependency and may land in any order relative to the others.
