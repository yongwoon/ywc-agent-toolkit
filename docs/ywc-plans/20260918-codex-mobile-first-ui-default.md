# Codex Mobile-First UI Default

> Status: Draft
> Scale: Medium
> Created: 2026-09-18
> Author: Codex
> Spec Reference: GitHub yongwoon/develop-with-llm PR #239

## Global Constraints

- Codex skills under `codex/skills/` are source of truth; `plugins/ywc-agent-toolkit/skills/` is generated by `bash scripts/sync-codex-plugin.sh`. (`codex/AGENTS.md`)
- Codex skill frontmatter contains only `name` and `description`. (`CLAUDE.md`)
- Required checks are `bash scripts/run-codex-skill-contract-evals.sh` and `bash scripts/validate.sh`. (`CLAUDE.md`)

## Purpose

Adopt PR #239's mobile-first default for Codex-only UI work. New end-user UI starts at the narrowest viewport and expands with `min-width`; a stated PC/tablet-only surface remains an allowed exception.

## Scope

- Add one shared Codex policy reference.
- Link it from Codex planning, scaffolding, task generation, sequential execution, the parallel worker prompt, and the bounded TypeScript reviewer.
- Add a deterministic source-contract check plus a TypeScript-reviewer eval, then regenerate the Codex plugin package.

## Out of Scope

- Claude Code changes, parity-policy changes, existing-CSS rewrites, framework-specific breakpoint values, and visual-design prescriptions.
- New Codex custom-agent roles or changes to agent sandbox/model contracts; this plan extends only the existing read-only `ywc-typescript-reviewer` review rule.

## Quality Gate Contract

- **Target:** Each targeted Codex planning/execution/agent-review surface exposes one consistent, conditional mobile-first contract.
- **Quality threshold:** A deterministic checker verifies the shared reference, five skill consumers, and the TypeScript-reviewer directive for trigger, `min-width` order, exception, and no-retrofit semantics; no consumer applies it to non-UI work or unscoped legacy CSS.
- **Evidence:** The named deterministic checker, its agent-eval fixture, package sync, `git diff --check`, and `bash scripts/validate.sh`.
- **Stop condition:** Stop if consumer wording disagrees on trigger, viewport order, breakpoint direction, exception, or generated-package parity.

## Acceptance Criteria

- [ ] **AC1 — Canonical policy:** The shared reference defines narrowest-viewport base styles, outward `min-width` expansion, no desktop-first `max-width` claw-back, an end-user-UI trigger, a PC/tablet-only exception for an otherwise in-scope end-user surface, and no retrofit obligation.
- [ ] **AC2 — Planning capture:** End-user frontend scaffolds and UI-touching Medium/Large plans record the policy; a genuinely end-user PC/tablet-only surface records the exception. Admin/internal tools are outside the trigger and require neither policy nor exception.
- [ ] **AC3 — Execution and review continuity:** A generated `ui` task that changes layout/style places the mobile base-layout step before `min-width` expansion; sequential and parallel workers read the reference before such work; the bounded TypeScript reviewer reports a Framework-idiom finding only when an in-scope TS/JS UI diff violates it.
- [ ] **AC4 — Bounded applicability:** Non-UI work, unchanged legacy desktop-first UI, and explicitly PC/tablet-only work gain no rewrite requirement.
- [ ] **AC5 — Distributable contract:** Targeted evals, plugin sync, full validation, and source/generated mirror checks pass.

## Functional Requirements

### FR-1: Publish one shared policy

Create `codex/skills/references/mobile-first-ui.md` with Rule, Trigger, Escape hatch, and Backward compatibility sections. It applies only to new end-user UI: base styles target the narrowest viewport and later additions use `min-width`.

### FR-2: Capture policy before implementation

Update the plan NFR template and project-scaffold supplementary guidance. Both link to the policy, restrict it to end-user UI, and require exceptions to be stated rather than inferred.

### FR-3: Carry policy into tasks and workers

Update task-generator step requirements and the sequential/parallel executor skill bodies. They direct workers to read the reference before layout/style code, create mobile base styles first, then extend with `min-width`; skip only when the task explicitly states the exception.

### FR-4: Lock the contract with evals

Extend `scripts/run-codex-skill-contract-evals.sh` with a deterministic `check_mobile_first_ui_contract` function. It must read the new shared reference, the five named skill files, `codex/agents/ywc-typescript-reviewer.toml`, and its eval record; assert each consumer links to or names the policy, assert trigger, `min-width`, exception, and no-retrofit tokens, and reject a missing or inconsistent consumer. Add a `ywc-typescript-reviewer` scenario to `codex/agents/evals/evals.json`; invoke the existing agent-eval checker from the same verification sequence. This documented runner limitation is the reason the generic skill-contract runner changes.

### FR-5: Extend the existing TypeScript reviewer

Update `codex/agents/ywc-typescript-reviewer.toml` with a bounded Framework-idiom check. It applies only when the evidence packet identifies end-user UI and the TS/JS diff changes layout/style behavior; it reads the shared policy and flags desktop-first claw-back patterns. It must preserve the agent's read-only scope, skip legacy UI absent an explicit redesign, and return `NEEDS_CONTEXT` rather than infer end-user/desktop-only intent.

### FR-6: Generate and validate package

Run source-level checks first, synchronize the plugin, review its generated diff, and run full validation.

## Edge Cases

- An admin dashboard or internal tool is outside the trigger; it receives neither the policy nor an exception-recording requirement.
- New work touching a desktop-first page preserves it unless responsive redesign is explicitly scoped.
- A `ui` task changing view logic but no layout/style applies the instruction only if it writes layout/style code.
- Product-specific breakpoint values are allowed; the policy governs `min-width` direction, not numeric values.

## Risks and Rollback

- **Risk:** The default is mistaken for an order to refactor existing CSS. **Mitigation:** Repeat new-surface-only/no-retrofit boundaries in reference and evals.
- **Risk:** An internal tool gets an unsuitable requirement. **Mitigation:** Keep admin/internal tools outside the trigger; reserve the exception for end-user PC/tablet-only surfaces.
- **Risk:** Consumer wording drifts. **Mitigation:** Centralize semantics and test links/conditions.
- **Rollback:** Revert source and eval changes, run `bash scripts/sync-codex-plugin.sh`, then validate; plugin output is reproducible.
