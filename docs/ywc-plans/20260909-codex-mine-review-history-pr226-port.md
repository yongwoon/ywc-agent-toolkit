## Purpose

Port PR #226's confirmation-first workflow for mining a window of merged-PR bot
review comments into evidence-based recurring defect classes. This fills the current
Codex gap between `ywc-review-learnings` (project-local learning capture) and the
shared recurring-defects catalog that `ywc-impl-review` already consumes.

## Outcome Oracle

- **Target:** A discoverable Codex skill safely converts a user-confirmed, bounded window of merged-PR bot comments into classified, deduplicated, confirmation-gated review-memory proposals, with the generated marketplace package in sync.
- **Quality threshold:** All source skill structure, exact CLI and NDJSON contracts, candidate-evidence rules, distinct-PR recurrence, runtime write authority, catalog entries, and hermetic helper-test cases are specified; source/package and repository validation pass.
- **Evidence required:** The new helper's mocked shell tests prove invalid-input exit 2/no `gh`, merged-window selection, anchored allowlist/NDJSON output, per-PR error continuation/nonzero exit, and no duplicate-PR recurrence; JSON, install-list, sync, package-freshness, and full validation commands pass.
- **Stop condition:** Do not hand off to task generation until `ywc-spec-validate` reports no Critical or Warning findings, the Blind Spot action is `proceed`, and every listed evidence command succeeds.

## Acceptance Criteria

- [ ] **AC1 — Activation:** When a user requests historical mining across many merged PRs, Codex selects this skill; single-PR, open-review, live-incident, and implementation-review requests route to their existing siblings.
- [ ] **AC2 — Fetch safety:** Given the skill's optional `--repo` (current repo fallback), a confirmed scope, and an effective positive `--limit`, it invokes the positional helper grammar shown in Module Boundaries. The helper selects the first N merged-PR records returned by its declared repository-scoped `gh pr list` query, applies optional `mergedAt >= YYYY-MM-DDT00:00:00Z`, and emits one NDJSON item per allowlisted bot review comment, including null/outdated anchors. Invalid/repeated values exit 2 before `gh`; per-PR API failures yield a diagnostic and nonzero final exit.
- [ ] **AC3 — Classification:** A comment is `DO` only with both resolved-thread and later-fix evidence; it is `FALSE-POSITIVE` only with a reasoned human dismissal. A comment lacking both evidence paths is dropped and accounted for.
- [ ] **AC4 — Recurrence:** Multiple comments in one PR add exactly one recurrence; only classes at `--min-recurrence` (default 3) distinct PRs qualify for the shared catalog.
- [ ] **AC5 — Write authority:** Before any durable write, the skill presents the whole changeset (cluster, classification, recurrence, PRs, target, text) and waits for confirmation. Project-local entries delegate to `ywc-review-learnings --source mining`; threshold-reaching shared-catalog entries are deduplicated, provenance-bearing maintainer proposals and are never written by the runtime skill.
- [ ] **AC6 — Distribution:** The Codex skill catalog and routing guide list the skill; root README locale counts equal the source-directory count after addition; the synchronized marketplace has the same files and executable mode.
- [ ] **AC7 — Agent boundary:** No Codex custom-agent TOML changes are made, and `bash scripts/install.sh --list --codex-agents` still reports the present agent catalog.

## Functional Requirements

### FR1 — Skill, metadata, and localized documentation

Create `codex/skills/ywc-mine-review-history/SKILL.md` with only Codex frontmatter,
batch-mining triggers and sibling anti-triggers, announce text, arguments (`--repo`,
`--limit`, `--since`, `--min-recurrence`, `--dry-run`), rationale defenses, and the
seven-step scope/fetch/classify/cluster/route/confirm/report workflow. Use Codex
`$ywc-*` notation: below-threshold candidates hand off to
`$ywc-review-learnings --mode update --source mining`, with the cluster evidence
supplied as context; never a Claude slash command or a direct project-file edit. Extend
that sibling's allowed `--source` values, capture-source reference, and eval fixture so
`mining` requires the aggregated distinct-PR list, representative evidence, rule, why,
polarity, and the same user-confirmed changeset as every existing source. Update all
six existing localized `ywc-review-learnings` README files (`README.md`, `.en`, `.ja`,
`.ko`, `.zh`, `.es`) so their exhaustive source grammar and handoff guidance include
`mining`; package synchronization then copies those source docs.

The skill resolves `--repo <owner/repo>` or its current repository via `gh repo view`,
then invokes the positional helper. It asks for a scope when both `--limit` and
`--since` are absent. An explicitly supplied `--since` selects a date window and uses
the default `--limit 200` as its upper bound; an explicitly supplied `--limit` selects
the first N merged-PR records returned by the documented CLI query; supplying both
applies `--since` inside that bounded returned set. `--limit` and `--min-recurrence` must each be a positive integer,
duplicate flags are usage errors, and date input is an ISO UTC date whose inclusive
boundary is `mergedAt >= <date>T00:00:00Z`. The report names this ordering, the actual
selected PR count, and the earliest/latest selected `mergedAt` values. Create the four
required README locales and `agents/openai.yaml`. Add zh/es READMEs only through the
normal translation workflow if this new skill participates in it.

### FR2 — Hardened bulk-fetch helper

Add executable `scripts/fetch-bulk-review-comments.sh` from PR #226's final hardened
revision: portable Bash with `set -euo pipefail`, usage/unknown-flag handling,
positive-integer and ISO-date validation, `gh`/`jq` checks, and a retained per-PR
failure status. Separate `gh api` from `jq` so a failed API call cannot be hidden by
filtering.

Use the case-insensitive anchored allowlist
`^(coderabbitai|chatgpt-codex-connector|github-actions)\[bot\]$`; reject every
other login in fixtures, including near-matching human names. Emit only `pr`, `id`, `path`, `line`, `body`, and
`in_reply_to_id`; explicitly document that this NDJSON omits resolution, human reply,
and zero-comment-PR information. The helper uses `gh pr list --repo "$REPO" --state
merged --limit <N> --json number,mergedAt`, and every REST/GraphQL request carries the
same resolved owner/repository. It treats the list command's returned order as the
bounded selection order before applying the UTC date filter; it does not claim a global
merged-date sort or silently paginate beyond its confirmed N-PR upper bound.

### FR3 — Classification, routing, and confirmation

For each first-pass candidate, use GitHub GraphQL scoped to
`repository(owner:, name:)` and the PR number. Paginate `pullRequest.reviewThreads`
and the nested `comments` connection for every candidate-matching thread; if either
connection cannot be fully read, conservatively drop/account for that comment. Map the
comment `databaseId` to its thread, `isResolved`, comment `createdAt`, and a non-bot
reply body/author when present. A resolved thread is `DO` only when a PR commit with
`committedDate > createdAt` has an exactly matching filename and a `+start,count` patch
hunk whose inclusive new-line range contains the comment's non-null `line`; query each
candidate commit's changed files through repository-scoped `gh api`. Missing/null/
outdated line anchors, renamed paths, unrelated hunks, or any unavailable evidence are
conservative drops. A reasoned non-bot reply explicitly rejecting the finding is
`FALSE-POSITIVE`; unavailable or ambiguous evidence is dropped/accounted rather than
promoted. Reuse the scoped merged-PR list for final scan count/date range. Cluster
generalized classes with polarity and distinct PR numbers. Every project-local cluster
delegates to the local owner through `--source mining`. Threshold-reaching clusters
read the full shared catalog, report any covering entry, or render an `A-NNN` proposal
with title/tags, scan cue, severity guide, and mining provenance for a separate
maintainer distribution PR; the installed skill never creates an `Appended entries`
section or modifies the packaged reference. `--dry-run` stops after the changeset; the
only runtime writes wait for explicit user confirmation and are performed by the
project-local owner.

### FR4 — Eval and catalog integration

Add `evals/evals.json` with scope-before-default, distinct-PR recurrence,
confirmation-before-write, insufficient-evidence-drop, and shared-catalog-proposal-only
scenarios. Add corresponding `ywc-review-learnings` `mining`-source fixtures. Add one skill-table row near
`ywc-review-learnings` and one routing-guide row to `codex/skills/README.md`; make
the periodic/batch boundary explicit. Add a hermetic
`scripts/test_fetch_bulk_review_comments.sh` (mocking `gh` and `jq` through `PATH`)
that proves AC2 branches: invalid/repeated values exit 2 without calling `gh`, the
merged-window/date selection, anchored bot allowlist, NDJSON schema, and an individual
API failure's continuation plus nonzero final status. Add classification fixtures for
the two evidence paths, exact patch-hunk overlap, unrelated/renamed/null-anchor drops,
and a distinct-PR recurrence fixture. Update root `README.md`, `README.ko.md`, `README.ja.md`, `README.zh.md`, and
`README.es.md` by calculating—not assuming—the post-addition Codex skill count. Do
not change the custom-agent catalog.

## Data Model / API Contract

N/A — no database or HTTP API is added. The helper's stdout is one NDJSON item per
eligible comment:

```json
{"pr":123,"id":456,"path":"src/file.ts","line":42,"body":"...","in_reply_to_id":null}
```

This record is insufficient to infer resolution or replies; the workflow must obtain
that evidence from the documented GraphQL/thread and later-commit checks before
classification.

## Edge Cases

- Merged PRs but zero bot comments: succeed with zero fetched/clusters and report scoped PR count.
- Many same-class comments from one PR: count that PR once.
- One `gh api` failure: continue, diagnose, and exit nonzero.
- A GraphQL thread lookup, reply mapping, or later-fix check is unavailable or
  ambiguous: drop/account for the comment; do not infer a `DO` or `FALSE-POSITIVE`.
- Existing matching `A-NNN`: report it; propose no duplicate.
- Partial confirmation: apply only confirmed items and report the rest unpromoted.
